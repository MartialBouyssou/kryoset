Information confidentialité Kryoset

Cette page est un modèle opérationnel pour une instance auto-hébergée. L’administrateur de l’instance doit compléter les champs entre crochets avant de l’ouvrir à d’autres personnes.

Responsable du traitement

Responsable : [nom ou organisation]
Contact : [email de contact]
Instance : [domaine de l’instance]

Données traitées

  • Compte : nom d’utilisateur, statut actif/inactif, rôle admin, racines de stockage, appartenance à des groupes.
  • Sécurité : hash de mot de passe, état 2FA, version de session, cookies de session HttpOnly, jeton CSRF, tentatives de connexion, adresse IP dans les journaux.
  • Fichiers : noms, chemins, tailles, dates de modification et contenu des fichiers déposés par les utilisateurs.
  • Partages : chemin du fichier partagé, date d’expiration, compteur de téléchargement, protection par mot de passe.

Finalités

Les données sont utilisées pour authentifier les utilisateurs, appliquer les permissions, fournir le stockage de fichiers, gérer les quotas, tracer les événements de sécurité et permettre l’administration de l’instance.

Conservation

Les comptes et fichiers sont conservés tant que le compte existe ou jusqu’à suppression par l’administrateur. Les journaux d’audit sont conservés selon la configuration serveur, par défaut avec une rotation et une purge automatique. Les variables KRYOSET_LOG_RETENTION_DAYS et KRYOSET_LOG_MAX_TOTAL_MB permettent d’adapter cette durée.

Droits des personnes

Chaque utilisateur peut demander l’accès, la rectification ou la suppression de ses données auprès du responsable indiqué ci-dessus. Kryoset fournit un export de compte via l’API admin et la commande kryoset user export. La suppression complète des métadonnées peut être effectuée avec kryoset user purge.

Sécurité

Les mots de passe et secrets 2FA ne sont pas exposés dans les exports. Les sessions web utilisent des cookies HttpOnly et un jeton CSRF pour les actions sensibles. Les sessions sont invalidées après désactivation, changement de rôle admin ou changement de mot de passe. Les partages publics n’exposent pas le chemin interne complet avant téléchargement.

Sauvegardes

Si l’instance est sauvegardée, les sauvegardes peuvent contenir les fichiers, comptes, permissions et journaux. L’administrateur doit définir une durée de conservation et une procédure de restauration/suppression adaptée.
